# 滑动变阻器输入审查

## 1. 成熟来源

当前实现直接沿用以下可读HS2811项目的函数结构和判断顺序：

- `HS/26_03_27_1034/PROJECT_CHECK_COOL/main.c`
- `HS/26_06_24_SS039/PROJECT_MAIN_电解电容/main.c`
- `HS/26_06_24_SS039/PROJECT_MAIN_贴片电容/main.c`

没有引入一阶低通、浮点映射或新的MCU运行时辅助函数。滑阻业务仍位于10ms输入处理位置，最终状态收敛仍由`mode_change()`负责。

## 2. ADC数据形态

滑阻与电池、AD_FAN共用成熟`ADCDATA_COUNT/ADCDATA_SUM`采样框架，但结果形态不同：

- 电池和AD_FAN：废弃2次、累积8次、右移3位得到12位平均值。
- 滑阻：废弃2次、累积8次，直接保留累积和`AD_SLIDER_SUM`。

默认端点为：

```c
#define ADC_SLIDER_MIN_GEAR    31129UL
#define ADC_SLIDER_MAX_GEAR     1638UL
```

八次12位采样最大累积为32760，小于`u16`上限65535。规划器会拒绝溢出、重名、不同一次滤波或非法端点配置。

## 3. 稳态确认

运行中每个新`AD_SLIDER_SUM`按以下顺序处理：

1. 风扇必须已经由按键开启。
2. 必须未插充电器且`charge_num`不为0。
3. 端点外数据先钳位到实板标定范围。
4. `old_res_val=60000`表示尚未抓取基准，首个有效结果只建立当前基准。
5. 新结果与基准差值必须大于生成期计算的`ADC_DEADBAND`。
6. 连续达到`ADC_CONFIRM_COUNT`次才更新基准；中间一次回到死区立即清零确认计数。
7. 基准更新后用成熟整数比例公式映射到`gear_range.minimum`到`gear_range.maximum`。
8. 只有目标档位变化才调用`show_mode_change()`。

默认100档配置中，端点差29491，99个档位区间生成`ADC_STEP=297`，三档死区生成`ADC_DEADBAND=891`。

## 4. 单按键和状态所有权

- `KEY_CHECK()`只负责低有效消抖、短按和一次长按事件。
- `KEY_deal()`短按切换`fan_start`；开机先置`gear_range.minimum`并清空滑阻基准，关机只撤销风扇请求。
- 长按只在风扇开启、未充电且有电量时切换`COOL_EN`。
- `mode_change()`负责充电锁`charge_max_gear`、制冷关闭、零电关机、风扇故障关机、显示复位和滑阻基准清理。
- `AD_fan_deal()`继续负责成熟的有刷/无刷启停、7+3调压和16V保护，没有为滑阻改写。

## 5. 供电与睡眠

- `SLIDER_ON`正常工作态输出高，给滑阻分压电路供电。
- `file_sleep_mode()`由GPIO资源规划器把`SLIDER_ON`改为输出低。
- 睡眠前清除按键事件、`fan_start`、滑阻基准、确认计数和ADC就绪标志。
- 睡眠资格要求按键已经释放、没有待消费事件、风扇请求关闭，并保留200ms唤醒稳定保护。
- 当前仅`KEY`、`CHRG`和`STDBY`参与唤醒，滑阻ADC脚不参与唤醒。

## 6. 充电行为

检测到`CHRG`或`STDBY`有效后：

- `insert_flag=1`。
- 制冷关闭。
- 风扇已开时强制配置的`charge_max_gear`。
- 滑阻结果不再更新档位。
- 显示回到充电常态电量页。

拔出充电器后重置`old_res_val`和确认计数，下一轮滑阻完整结果重新抓取当前位置，不沿用充电前基准。

## 7. 必须实板验证

1. 实测1档和最大档的八次累积值，并更新两个端点。
2. 上电、睡眠唤醒和拔充电器后，当前滑阻位置是否能一次建立正确基准。
3. 静止时是否不跳档，慢推时是否不会因三次确认产生不可接受的迟滞。
4. 充电时是否始终锁配置的`charge_max_gear`、禁止制冷并忽略滑阻。
5. `SLIDER_ON`睡眠电平、整机静态功耗和按键唤醒。
6. 有刷/无刷识别极性、两套PWM寄存器、压降补偿和16V保护。
7. HSIDE/PICC程序空间、数据空间、堆栈、中断时长和校验码。

当前只完成生成器与静态回归测试，不能替代目标编译器和实板验证。
