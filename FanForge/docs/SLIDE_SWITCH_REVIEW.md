# SWI_KEY拨片开关审查

## 1. 当前支持范围

当前模块只生成已经按N68Y/N68Y1成熟结构核对过的组合：

- `SWI_KEY`低有效。
- MCU内部上拉。
- 开关接地时开机，释放为高电平时关机。
- 拨片独占产品开关机，按键只负责调档和其他已配置动作。
- 零电睡眠关闭拨片上拉并取消该脚唤醒。

高有效、内部下拉、外部偏置或不由拨片独占开关机的组合均会拒绝生成。

## 2. 函数边界

### `GPIO_Init()`

- 使用公共GPIO规划结果把`SWI_KEY`配置为输入上拉。
- 不判断风扇是否应开机。

### `KEY_deal()`

- 拨片关闭时清除待处理按键事件并直接返回。
- 拨片产品的档位循环在第一档到最高档之间循环，不产生档位`0`。
- 不清除`fan_error_flag`，避免按键绕过电机故障恢复条件。

### `mode_change()`

- `SWI_KEY`高电平时统一把`fan_mode`和`COOL_EN`清零，并清除`fan_error_flag`。
- `SWI_KEY`低电平、没有风扇故障、存在可用电量或已插入充电器时，从配置第一档启动。
- 风扇关闭后的显示、制冷和输出后果继续由原有公共状态归一逻辑处理。

### `file_sleep_mode()`

- 非零电量时只有拨片关闭才允许睡眠，拨片脚保持输入上拉和唤醒。
- 零电时允许拨片仍接地进入睡眠，关闭拨片上拉并移出唤醒掩码。
- CHRG/STDBY唤醒不受拨片零电隔离影响。
- 正常/零电寄存器值由GPIO规划器生成，函数内不写死物理脚。

## 3. 风扇故障恢复

固定占空比无刷产品发生AD_FAN超压后，`fan_error_flag`保持置位。只要拨片仍在开启位置，`mode_change()`就不会重新启动风扇。客户必须先把拨片拨到关闭位置，再重新开启，才能开始下一次检测。

这与成熟拨片产品“开关动作重新允许检测”的结构一致，不能改成任意按键清故障。

## 4. 生成期验证

生成器会检查：

1. 启用拨片时必须绑定`SWI_KEY`物理脚。
2. 当前极性必须是`low`，偏置必须是`up`。
3. `SWI_KEY`必须支持工作态数字输入和所需Port A唤醒。
4. 正常睡眠与零电睡眠分别计算端口方向、上下拉和`WUACON`。
5. 未启用拨片的旧配置不能因该模块改变生成源码。

## 5. 实板必须验证

1. 上电时拨片开/关两个位置的默认状态。
2. 正常电量下关闭后睡眠、重新拨开唤醒和启动。
3. 零电且拨片未关闭时的静态功耗。
4. 零电状态下拨片动作不会唤醒，插入充电器仍能唤醒。
5. AD_FAN故障后保持拨片开启不会反复重启，开关一次后才重新检测。
6. 睡眠和唤醒后CHRG/STDBY极性、充电显示和电量初始化不受影响。

当前只完成生成器测试，没有替代HSIDE/PICC编译和实板验证。
