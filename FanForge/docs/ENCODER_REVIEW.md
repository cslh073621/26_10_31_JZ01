# 旋转编码器输入审查

## 1. 当前支持范围

当前只生成已经按1025滚轮版本核对过的成熟组合：

- HS16P2811 Port A两相低有效旋转编码器。
- A、B两相内部上拉。
- 运行时只有A相开启Port A电平变化中断，B相只负责方向采样。
- A相下降沿和上升沿组成完整周期后才产生一次档位事件。
- 低有效拨片开关独占开关机，编码器只在开机后于配置的连续档位范围内调档。
- 普通每次调1档；500ms内达到配置次数后切换为每次调5档。

无拨片开关机、双相同时中断、外部偏置和编码器按压功能尚未开放。

## 2. 资源规划

功能模块分别声明`ENC_A`和`ENC_B`输入上拉，但只有`ENC_A`声明`runtime_change`。GPIO规划器验证该脚必须位于Port A且支持电平变化，并单独生成运行中断掩码。

运行态`Init_System()`按以下顺序配置：

1. 临时关闭`PAIE`。
2. 把`WUACON`写成只包含`ENC_A`的运行掩码。
3. 保存当前A相电平。
4. 读取`PORTA`清除失配条件。
5. 清`PAIF`后重新开启`PAIE`。

休眠掩码与运行掩码分开计算，编码器两相不进入睡眠唤醒。

## 3. 中断和滤波

`myIsr()`先读取`PORTA`再清`PAIF`，随后只处理A相变化：

- A相下降沿：记录当时的B相并标记周期开始。
- A相上升沿：读取反相B并结束周期。
- 两次采样均为高或均为低时，分别确认一个方向。
- 不匹配时丢弃，不生成档位事件。

滤波计数由Timer1固定节拍递减。生成器会考虑边沿到达的同一次中断也可能立即递减一次，因此生成值包含一个保护计数，确保实际屏蔽时间不短于配置的`filter_us`。

## 4. 档位和加速

`KEY_deal()`沿用成熟输入业务位置，但编码器配置不生成数字按键状态：

- 每次只消费一个待处理加档或减档事件。
- 普通档位步长由`normal_step`确定。
- 独立加速窗口结束时，根据窗口内有效编码器事件数确定下一窗口是否使用`accelerated_step`。
- 充电状态按`CHARGE_MAX_GEAR`限档，非充电状态按`FAN_MODE_MAX`限档。
- 加档不越过`gear_range.maximum`，减档不低于`gear_range.minimum`。
- 每次有效调档调用`show_mode_change()`，显示策略继续由公共显示模块处理。

加速窗口不与`time_flash_flag`共用事件，否则`KEY_deal()`清标志会破坏充电或低电闪烁。

## 5. 睡眠和清理

- 拨片关闭时`KEY_deal()`清除待处理事件。
- 睡眠资格等待加减事件队列清空，但不等待`encoder_cycle_flag`，避免用户停在半个机械周期时永久无法睡眠。
- `file_sleep_mode()`统一清除相位、滤波、方向、加速和待处理计数。
- 唤醒后的`Init_System()`重新读取A相当前电平，旧相位不会混入新周期。

## 6. 实板必须验证

1. 顺时针和逆时针方向是否与配置一致；不一致只翻转`clockwise_increases`。
2. 慢转每个完整机械格只变化一次。
3. 快速正反转不会产生大量反向积压。
4. 普通与加速步长、500ms窗口和充电限档符合产品要求。
5. 拨片关闭时转动编码器不会唤醒或阻止睡眠。
6. 零电睡眠、充电唤醒和风扇故障恢复不受编码器影响。
7. 目标HSIDE/PICC程序空间、堆栈和中断时长满足要求。

当前只完成生成器测试，没有替代目标编译器和实板编码器验证。
