# Luna实施任务：固定电压7+3与ADC采样重构

## 任务目标

根据F824实板闭环调试结果，修正FanForge当前固定电压7+3生成方案中的ADC采样相位问题，同时保留已经验证正常的7+3 PWM输出算法。

本任务只修改PC端生成器、生成文档、测试和由生成器重建的示例。不要直接修改任何量产项目，也不要把F824源码复制成新的核心模板。

## 实测依据

- 实测项目：`H:\WorkSpace\HS\26_07_21_F824`。
- 正式验证提交：`0771ea9`。
- 诊断归档：`H:\WorkSpace\HS\26_07_21_F824\资料\F824_7+3闭环诊断版_20260801`。
- T4硬件PWM为250kHz，7+3软件相位每100us推进一次。
- ADC每100us转换一次；每通道保持10ms窗口，共100次转换，丢弃前4次，将后96次按每8次先平均、再累计12组并除以12。
- 三通道完整轮询约30ms；每得到一个新的AD_FAN平均值只调整一次`PWM_DR/PWM_DATA_NOW`。
- 实测`PWM_DATA_NOW=36`、`PWM_DR`约1至2，`fin_state`在1和3之间变化，电机电压稳定在9.07V至9.09V，证明7+3输出算法有效。
- F824使用放大2倍的目标值、`AD_FAN_ERROR_WINDOW=180`。万用表实测通常比AD公式名义换算低约0.2V，因此该板目标值整体上移约0.2V。

## 当前生成器存在的问题

1. `configs/hs2811_classic_fixed_voltage_7_3.json`仍使用125us时基、丢2次加平均8次、误差窗口68和200ms慢调。
2. 生成的`ADC_Sample()`只在`time_1ms_flag`后调用。即使7+3每125us推进，ADC仍可能长期采到相近的软件相位。
3. `planner.py`当前只按“AD更新期间存在多少轮7+3”做校验，没有校验ADC采样是否覆盖8个相位。
4. 当前ADC模型只允许1、2、4、8、16次直接累加平均，无法表达F824已验证的“96个有效样本、每8个先平均”的防溢出结构。
5. 固定电压目标只有`target_adc_base + target_adc_step`，没有独立最大档目标；整数步长不能保证最高档准确吃到目标端点。
6. `slow_adjust_ms=200`会让细调在已有新AD_FAN结果时仍被额外阻塞，不符合F824验证后的“每个新平均值调整一次”。

## 不允许修改的部分

- 不重写7+3输出规则。继续使用8相计数和成熟判断：`PWM_DR > PWM_CNT`时输出`PWM_DATA_NOW + 1`，否则输出`PWM_DATA_NOW`。
- 不改固定占空比无刷逻辑。
- 不改有刷PWM逻辑和`YOUSHUA_WUSHUA`极性。
- 不改无刷启动`FAN_ON -> 约10ms -> PWM`和关闭`PWM -> 约10ms -> FAN_ON`顺序。
- 不改16V AD_FAN超压保护的物理上限，不给16V阈值叠加0.2V目标补偿。
- 不改电量分段、负载补偿、充放电追赶、按键、显示、充电、GPIO和睡眠业务。
- 不新增第二套独立的`AD_FAN_Sample()`；必须由统一ADC规划器生成一套`ADC_Init()`和`ADC_Sample()`。
- 不在T1中断内执行ADC转换；中断只置高频采样标志，主循环消费标志后调用`ADC_Sample()`。
- 不为本任务新建MCU业务函数或新的风扇状态机。

## 确定的目标设计

### 1. 7+3高频时基

- 固定电压7+3的标准HS2811配置默认使用100us T1中断。
- T1每100us推进一次`PWM_CNT`并更新PWM占空比寄存器。
- 每10个100us子节拍继续派生原有`time_1ms_flag`，1ms及以上时间系统不变。
- 7+3输出只在无刷风扇已经运行且对应PWM定时器开启时执行。

### 2. 统一ADC高频采样

- 只有启用固定电压7+3时，公共ADC计划切换为高频采样模式。
- T1中断每100us置一个高频ADC标志；启动自检和正常主循环都消费该标志并调用一次原有`ADC_Sample()`。
- 所有启用的ADC通道共享同一高频轮询，不为AD_FAN单独建立采样函数。
- 每个通道：
  - 总转换数100。
  - 丢弃前4次。
  - 后96次有效。
  - 每8次先右移3位形成一个小组平均。
  - 12个小组平均累加到一个共享`u16 ADC_GROUP_SUM`。
  - 通道结束时使用`ADC_GROUP_SUM / 12`得到0至4095的12位平均值。
- `ADCDATA_SUM`最多累加8个12位值，`ADC_GROUP_SUM`最多累加12个12位平均值，两者都不能溢出`u16`。
- 每通道更新周期仍约10ms；N个通道完整扫描周期为`N * 10ms`。
- 电池二级16次平均、AD按键解码和滑阻结果模式继续使用各自已有业务结构，不改变其含义。

### 3. AD_FAN结果消费

- 每个AD_FAN通道平均完成后只置一次`ad_fan_ready_flag`。
- `AD_fan_deal()`只在该标志为1时执行一次超压判断和一次闭环调整，消费后立即清标志。
- 默认不再使用额外200ms慢调门槛；大误差和小误差都只随新的AD_FAN平均值更新。
- 若保留`slow_adjust_ms`兼容字段，必须允许明确关闭，并且固定电压标准配置默认关闭。不要让旧字段继续生成无意义计数器和标志位。

### 4. 目标值、最大端点与误差窗口

- 固定电压配置必须支持独立的：
  - 最小档目标。
  - 每档步长。
  - 最大档目标。
  - 测量倍率。
  - 误差窗口。
- `Get_Fin_Val()`保持成熟线性累加写法；当`fan_mode`达到配置的最大档时，强制使用独立最大档目标，避免整数步长截断。
- 标准固定电压配置默认`error_window_adc=180`，该值单位是已经乘过`measurement_multiplier`后的比较值。生成报告必须明确单位。
- 误差窗口继续允许产品配置覆盖，不要硬编码成所有项目不可修改的180。

### 5. 0.2V实测标定

- 0.2V只属于固定电压控制目标的板级经验标定，不属于ADC参考电压修正，也不属于安全保护修正。
- 配置层应能明确表达目标标定偏移，不能在发射器里偷偷加常数。
- 推荐增加`target_calibration_offset_mv`，标准100K:10K、2V参考配置默认可设为200；配置设为0时不得补偿。
- 生成器根据目标电压、分压电阻、ADC参考、测量倍率和偏移计算最终目标ADC常量，或者在兼容旧原始ADC配置时把两种模式严格互斥。不能同时接受物理电压和原始ADC字段后静默选择其一。
- 16V超压阈值继续按物理16V、100K:10K和2V参考独立换算，绝不能叠加`target_calibration_offset_mv`。
- 电池阈值和AD按键阈值同样不能使用该偏移。

### 6. 规划器校验

- 给ADC计划增加真实的采样周期信息，不能继续默认“一次样本等于1ms”。
- `scan_cycle_ms`必须从`sample_period_us * 每通道总样本数`计算。
- 固定电压7+3必须校验：
  - 高频ADC采样周期与7+3相位推进周期一致。
  - 有效样本数至少覆盖完整8相。
  - 有效样本数是8的整数倍。
  - 两级累加均不溢出`u16`。
  - ADC转换最坏耗时小于高频采样周期。
- 删除或替换当前只计算`complete_7_3_cycles`的伪校验；它不能证明ADC覆盖了不同相位。

## 配置兼容要求

- 现有非固定电压33套配置生成的MCU运行代码除版本注释和必要报告字段外应保持不变。
- 固定占空比、纯有刷和未启用AD_FAN的配置仍使用原有1ms ADC采样模式。
- 严格字段白名单和`capabilities`配置契约必须同步更新。
- GUI通过配置契约读取新增字段，不在GUI里复制第二套计算逻辑。
- 如果增加物理电压目标模式，旧原始ADC字段必须有明确兼容或明确迁移错误，不能静默改变旧项目目标值。

## 必须增加的自动测试

1. 100us固定电压配置生成高频ADC标志和主循环调用，ADC调用不进入ISR。
2. 生成的ADC代码包含4次废样、96次有效样本、8样本分组和12组平均。
3. 生成计划报告每通道10ms、三通道30ms，而不是把100次误算为100ms。
4. ADC有效样本覆盖8相；不满足时配置拒绝。
5. 两级`u16`累加边界校验。
6. 最大档使用独立最大目标。
7. 0.2V偏移只改变最小/最大闭环目标常量。
8. 16V超压阈值在偏移为0和200时完全相同。
9. 非固定电压配置不生成`ADC_GROUP_SUM`、高频ADC标志或7+3变量。
10. 固定电压标准配置不生成200ms慢调标志和计数器。
11. 所有原有测试继续通过。
12. 全部示例重生成后无残留占位符，`git diff --check`通过。

## 停止条件

出现以下任一情况时停止实施并留下说明，不要自行猜测：

- HS2811手册中的ADC转换时间无法证明小于100us。
- 为实现高频统一ADC必须改变电池、按键或滑阻业务含义。
- 0.2V偏移与旧原始ADC字段无法在不静默改变行为的情况下兼容。
- 非固定电压示例产生了无法解释的MCU运行代码变化。
- 生成代码ROM/RAM明显增加，但没有给出资源差异和原因。
