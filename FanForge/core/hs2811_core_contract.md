# HS2811风扇核心契约

## 1. 核心的含义

本核心不是某个历史项目，也不是可供AI选择的模板列表。它是从成熟HS2811风扇项目中提取出的唯一源码骨架。

当前阶段固定：

- 源码章节顺序。
- 函数排列顺序。
- 上电、自检、运行和睡眠四个阶段。
- 各函数的职责边界。
- 主循环内各类处理的先后关系。
- HS2811标志位统一使用芯片原生`bit`类型，不使用字节联合体模拟位变量。

当前阶段不固定：

- 某个具体产品最终是否保留某个功能函数。
- 各函数使用哪一种成熟功能变体。
- 脚位、寄存器值、阈值和灯板映射。

## 2. 固定运行阶段

### 上电初始化

1. 配置系统基础寄存器。
2. 配置GPIO安全初始状态。
3. 初始化ADC、定时器和PWM寄存器。
4. 关闭或安全化全部输出。
5. 开启系统时基和看门狗。

### 全亮自检

1. 设置约2秒的`delay_cnt`。
2. 显示类产品置全亮缓存。
3. 保持时间标志处理运行。
4. 每个采样节拍调用`ADC_Sample()`。
5. 每个循环或固定节拍清看门狗。
6. 电量类产品只允许在该阶段直接初始化`charge_num`。
7. 可选硬件检测只能占用自检末段，结束后必须恢复端口模式。

### 正常运行

固定处理顺序：

1. ADC采样与看门狗。
2. 时间标志派生。
3. 输入消抖和事件处理。
4. 显示阶段切换。
5. `mode_change()`统一收敛共享状态。
6. 风扇、显示和其他输出根据稳定状态执行。
7. 最后判断是否允许睡眠。

### 睡眠与唤醒

1. 先执行统一关输出流程。
2. 清空显示和未完成事件。
3. 配置睡眠GPIO方向、上下拉和唤醒端口。
4. 关闭ADC、PWM和不需要的定时器。
5. 关闭WDT后睡眠。
6. 唤醒后恢复WDT并重新调用`Init_System()`。
7. 等待输入或ADC重新稳定后，才允许再次睡眠。

## 3. 固定职责边界

### `myIsr()`

- 只产生固定时间基准。
- 只执行必须保持固定频率的扫描或PWM细分。
- 编码器产品允许在Port A变化中断内完成A相边沿、B相采样和整周期确认，但只累计输入事件，不执行产品动作。
- 不执行产品模式切换、电量映射或复杂按键动作。

### `GPIO_Init()`

- 只负责GPIO初值、方向、上下拉、开漏和模拟口配置。
- 所有输出先进入安全状态。
- 不判断产品功能。

### `ADC_Init()`

- 配置ADC公共时钟和初始通道。
- 清空采样计数、累加值和依赖连续采样的保护计数。
- 不计算电量或处理按键动作。

### `timer1_init()`

- 名称与实际使用的T1系统时基保持一致。
- 根据系统主频、T1时钟源、分频和目标基础周期配置T1。
- 只设置定时器、重载值、标志位和中断使能。

### `pwm_init()`

- 只配置周期、路由和初始零占空比。
- 不启动负载。

### `Init_System()`

- 固定调用GPIO、ADC、定时器和PWM初始化。
- 不承载产品按键或模式动作。

### `ADC_Sample()`

- 固定执行通道切换、启动转换、超时保护、12位数据组装、丢弃不稳定样本和累加；根据资源请求输出平均值或累积和。
- 一组完成后只把结果写入功能模块声明的结果变量，电量通道可继续执行二级平均。
- 按键阈值、电量百分比、档位映射和风扇控制由各自的成熟业务函数处理。
- 不重新设计电量映射。

### `time_flag_deal()`

- 只从基础计数派生更慢的时间标志。
- 不执行对应产品动作。

### `KEY_CHECK()`

- 只负责消抖、长短按计时和事件置位。
- 不直接开关风扇、制冷、雾化或灯光。
- AD按键产品必须先把完成平均的新ADC值解码为与数字按键相同的低有效`KEYx`状态，再进入本函数；本函数本身不区分输入硬件来源。
- 滑阻产品在本函数生成低有效单按键事件；滑阻ADC档位确认不塞进按键消抖。

### `KEY_deal()`

- 只消费已经确认的输入事件。
- 修改产品请求状态，不直接重写公共关机后果。
- 拨片开关产品中，按键不得绕过拨片开关机，也不得清除必须通过拨片重新动作才能恢复的风扇故障。
- 编码器产品继续在本函数消费加减档事件和处理档位边界，不新建第二个产品动作函数。
- 滑阻产品在本函数消费短按开关风扇和长按制冷事件，档位由滑阻结果单独更新。

### `mode_change()`

- 统一处理输入状态归一、充电限制、风扇关闭连锁、低电关机、显示复位和输出状态收敛。
- 相同后果不得分散复制到多个按键和保护分支。

### `show_mode_deal()`

- 根据稳定状态构造显示缓存。
- 不在扫描函数里临时推导产品状态。

### `smg_close()` / `smg_188_scan()`

- 只处理灯脚安全空闲态和动态扫描。
- `Data[]`位关系与物理灯板映射必须由固定映射数据产生。

### `AD_fan_deal()`

- 统一处理电机启动、运行、关闭和必要保护。
- 有无刷启停顺序必须由已验证变体提供。

### `v_bat_deal()`

- 固定保留“测量值处理、负载补偿、分段映射、低电判断、充放电定时追赶”的成熟结构。
- 非上电初始化路径不得直接让未充电电量向上回升。

### `file_sleep_mode()`

- 是睡眠硬件配置的唯一入口。
- 必须在全部功能关闭且输入事件窗口完成后调用。
- AD_KEY复用唤醒时，正常态模拟输入与睡眠态数字输入上拉必须由同一资源声明统一规划，不能在业务函数中临时改脚位。
- 拨片产品的正常睡眠与零电睡眠上下拉、唤醒掩码必须由GPIO规划器分别生成；业务函数只能提供`charge_num`状态，不能临时拼寄存器值。
- 编码器运行中断掩码与睡眠唤醒掩码必须分开规划，编码器残余相位和事件在睡眠入口统一清除。
- 滑阻供电脚、ADC脚和单按键的工作/睡眠状态必须由同一GPIO/ADC资源计划生成，睡眠前清除基准和连续确认状态。

### `main()`

- 只负责固定阶段和固定调度顺序。
- 不直接实现复杂产品动作。

## 4. 当前核心不可加入的内容

- 具体按键操作。
- 编码器判向。
- 具体有刷或无刷PWM公式。
- 具体充电芯片状态协议。
- 电池阈值和压降补偿值。
- 具体数码管段位映射。
- 制冷、雾化、照明、RGB和步进电机逻辑。

这些内容以后只能由应用内部的已验证规则填入固定插槽。

## 5. 标志位存储规则

- HS2811直接支持`bit`类型，所有布尔状态和时间标志统一声明为原生`bit`。
- 禁止使用`bit_flag`、`flag.bits.bit0`等字节联合体模拟方式。
- 其他不支持原生`bit`的平台以后由独立芯片适配层选择存储方案，不得反向污染HS2811核心模板。
